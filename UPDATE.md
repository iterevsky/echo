# Как обновлять сайт «ЭХО»

Короткая памятка для локальной работы и публикации.

## 1. Редактирование файлов

Сайт статический: `index.html`, `style.css`, `script.js`, `chapters.js`, `sw.js`,
плюс `images/`, `fonts/`, `icons/`. Правь файлы как обычно, в любом редакторе.
Никакой сборки нет.

## 2. Когда поднимать CACHE_VERSION

В начале `sw.js` есть строка вида `const CACHE_VERSION = 'echo-v45';`.

**Перед публикацией любого изменения файлов сайта** (`index.html`, `style.css`,
`script.js`, `chapters.js`, картинки, шрифты, иконки) увеличь номер на 1:
`echo-v45` → `echo-v46`. Иначе читатели получат старый кэш.

Изменения только документации (`README.md`, `UPDATE.md`) и локальных
помощников (`push-echo.cmd`, `tests/`) бампа не требуют.

## 3. Локальная проверка

Нужен установленный Node.js (https://nodejs.org): `push-echo.cmd` перед
публикацией обязательно прогоняет `node --check script.js` и
`node --check sw.js` — без Node публикация остановится.

```bat
pwsh -NoProfile -File tests\run-static.ps1
```

Структурные проверки: целостность chapters.js, соответствие оглавления,
существование precache-файлов, контроль CACHE_VERSION.

Для проверки в браузере подними локальный сервер (в отдельном окне):

```bat
pwsh -NoProfile -File tests\serve.ps1 -Port 8734
```

и открой http://127.0.0.1:8734/ — сервис-воркер и офлайн работают только по HTTP,
не по file://.

## 4. Публикация одним двойным щелчком

Дважды щёлкни `push-echo.cmd` в корне проекта. Скрипт:

1. показывает ветку и список изменений;
2. прогоняет структурные проверки (в т.ч. контроль CACHE_VERSION);
3. спрашивает сообщение коммита (Enter = «Обновление сайта»);
4. просит одно подтверждение (`y`);
5. делает `git add -A`, коммит, `git pull --rebase`, `git push`.

Токены и пароли не нужны — используется сохранённая авторизация git.

## 5. То же самое вручную

```bat
git add -A
git commit -m "Описание изменений"
git pull --rebase
git push
```

## 6. Если pull --rebase сообщает о конфликте

Ничего не потеряно. В папке появятся файлы с метками `<<<<<<<`.

1. Открой конфликтующие файлы, оставь нужные варианты, удали метки.
2. Выполни:

```bat
git add -A
git rebase --continue
git push
```

Отменить весь rebase и вернуться к состоянию до pull:

```bat
git rebase --abort
```

## 7. Проверка после публикации

GitHub Pages обновляется не мгновенно: подожди 1–2 минуты, затем открой
https://iterevsky.github.io/echo/ и обнови страницу с обходом кэша (Ctrl+F5).
Статус сборки виден на GitHub: репозиторий → Actions или Settings → Pages.

## 8. Отменить незакоммиченную правку

Один файл:

```bat
git checkout -- имя-файла
```

Все незакоммиченные изменения разом (не трогает уже сделанные коммиты):

```bat
git checkout -- .
```

Новые (ещё не отслеживаемые) файлы это не удаляет — их можно просто стереть
руками.
